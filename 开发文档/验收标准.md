# LumeKit 验收标准

更新时间：2026-10-11

说明：下面只有明确标注“已验证”的项目才是通过状态，其余全部还没验证。真实设备验收按当前计划暂缓。

## 1. 构建与启动

- [x] Debug 配置可以成功生成（已验证：命令行 `dotnet build -c Debug -p:Platform=x64` 为 0 个错误、100 个警告）。
- [ ] 目标平台至少完成 x64 验证。
- [ ] 应用可以启动、打开主窗口并进入设置页面。
- [ ] 没有因为缺少蓝牙设备、摄像头或显示器能力而直接退出。

## 2. 音频功能

- [ ] 可以显示可用的蓝牙音频设备。
- [ ] 可以连接和断开设备。
- [ ] 可以区分输入和输出设备。
- [ ] 可以切换输出路由。
- [ ] 输入音量调整结果与系统实际状态一致。
- [ ] 设备不可用或操作失败时有明确提示。

## 3. 快捷键和托盘

- [ ] 快捷键可以触发配置的音频路由动作。
- [ ] 托盘图标可以正常显示、点击和退出。
- [ ] 托盘面板不会遮挡或脱离可用屏幕区域。
- [ ] 应用重启后设置仍然保留。

## 4. 自动化

- [ ] 可以创建、编辑、保存和删除自动化规则。
- [ ] 触发器和条件按预期匹配。
- [ ] 动作按配置顺序执行。
- [ ] 动作成功和失败都有明确通知或日志结果。
- [ ] 规则执行不会阻塞主界面。
- [ ] 自动化失败时可以按配置继续、重试或中止（代码已支持 Continue/Retry/Abort，但未在真机验证）。

## 5. 主题、亮度和效率

- [ ] 深色/浅色主题可以切换。
- [ ] 背景效果不可用时可以降级显示。
- [ ] 亮度功能在支持的显示器上有效。
- [ ] 自动亮度和自动昼夜主题在开启/关闭后行为正确。
- [ ] 后台效率和电源相关操作失败时有明确原因。

## 6. 通知和浮层

- [ ] 普通通知可以显示、自动关闭和手动关闭。
- [ ] 通知内容不会超出窗口。
- [ ] DeskBox 浮层测试入口可以单独验证尺寸、材质、主题和动画。
- [ ] 新浮层未正式替换旧业务前，旧通知和托盘功能不受影响。

## 7. 文档一致性

- [ ] 技术方案只描述当前已存在或明确标注为计划中的内容。（2026-10-05 体检发现不符合，已在 `技术方案.md` 中修正。）
- [x] 开发计划只更新任务状态和进度百分比，不记录过程日志。
- [ ] 重大技术选择写明来源、原因和限制。
- [ ] 每次验收后同步变更记录。（2026-10-02 之后漏记，已在 `变更记录.md` 中补上。）
- [x] 开发文档目录只保留 5 份主文档，旧方案和重复文档归档到 `docs/archive/`。（2026-10-11 已整合）

## 8. 浮层（DeskBox 风格）

说明：本节由原 `LumeKit 浮层设计规范.md` 的设计验收标准和 `DeskBox与LumeKit浮层实现对比.md` 的代码审查点合并而来，两份文档已归档到 `docs/archive/`。当前浮层只有独立测试版，旧通知和托盘业务未切换，下列项目全部还没验证。

### 8.1 设计验收（每完成一种浮层后至少检查）

- [ ] 深色和浅色主题都能看清。
- [ ] 中文长文本不会被截断得难以理解。
- [ ] 菜单项不会因为文字变长而互相挤压。
- [ ] 浮层不会跑出屏幕工作区。
- [ ] 点击外部能正确关闭需要关闭的浮层。
- [ ] 通知不会挡住托盘快速面板，除非用户明确允许。
- [ ] 悬停和按下状态足够明显，但不刺眼。
- [ ] 三种浮层看起来属于同一个 LumeKit。
- [ ] 关键尺寸都能从统一入口调整。

### 8.2 测试浮层视觉（对照 DeskBox 原项目和引用图片）

- [ ] 浮层不过大也不过小。
- [ ] 内容垂直居中。
- [ ] 图标和文字间距一致。
- [ ] 背景不过亮也不过暗，边框明显程度合适。
- [ ] 圆角一致。
- [ ] 动画是从下往上出现、向下消失，出现和消失速度自然。
- [ ] 没有误改普通通知和托盘菜单。

### 8.3 代码审查点

1. 公共资源完成后：是否直接对应 DeskBox 原项目资源；是否只是搬运、没有加入无关设计；是否影响现有托盘菜单；是否影响普通通知；资源名称和来源是否写清楚。
2. 测试入口完成后：是否已经完全去掉快捷键测试依赖；是否只调用测试通知；是否没有改变现有快捷键功能；是否没有增加新的全局设置；点击后是否能稳定弹出浮层。
3. 测试浮层视觉确认后：是否以 DeskBox 原项目和引用图片为准；是否误改普通通知或托盘菜单；动画方向和时长是否与 DeskBox 原代码一致；公共参数是否仍然集中管理。
4. 材质实现完成后：是否直接沿用 DeskBox 的材质处理思路；Windows 不支持时是否能正常降级；浅色和深色主题是否正常；是否影响通知窗口关闭和重新显示；是否引入了不必要的私有改写。
5. 动画控制完成后：是否真的使用 DeskBox 的动画控制方式；是否处理动画中断、重复触发和快速隐藏；是否存在定时器和 Composition 动画同时控制同一对象；是否影响窗口关闭和通知队列；是否仍保持从下往上出现、向下消失。
6. 每推广一类通知后：当前通知是否使用公共 DeskBox 外壳；普通通知内容是否保持原有功能；通知队列、自动隐藏和合并通知是否正常；托盘面板打开时的隐藏规则是否正常；是否可以只回退这一类通知。

### 8.4 审查总原则

- 每个阶段完成后先审查再进入下一阶段，不把多个阶段一次性混在一起。
- 每次审查回答四个问题：改动是否来自 DeskBox 原项目或已确认的 LumeKit 需求；是否改变了本阶段之外的功能；是否保留现有功能和回退路径；下一阶段是否仍符合“先测试、后推广”的顺序。
- 审查发现偏离目标时：暂停下一阶段 → 标出偏离的文件和代码 → 先修正方案 → 重新审查。

### 8.5 落地前的待定口径

以下两处冲突未确认前，浮层尺寸和动画按哪套数值实现都不算验收通过：

- 托盘快速面板宽度：`技术方案.md` 第 5 节按原设计规范记 `650`，原对比文档记录 `TrayQuickPanelWindow.xaml` 实际值为 `260 x 400`。
- 测试浮层动画时长：`技术方案.md` 第 5 节按原设计规范记显示 `300ms` / 隐藏 `200ms`，原对比文档记录已搬入 DeskBox 的入场 `210ms` / 退场 `150ms`。
