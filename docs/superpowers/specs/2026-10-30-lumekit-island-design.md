# LumeKit 灵动岛设计需求

## 目标

为 LumeKit 增加仅展示本应用自身状态的顶部交互浮层。它借鉴灵动岛的胶囊形态、收起/展开和状态提示，不追求复刻手机系统的完整效果；复用现有 `DeskBoxFloating` 窗口外壳、动画和材质，且不改变普通悬浮通知行为。

## 已确认范围

- 只呈现 LumeKit 自身事件，不读取或展示第三方应用媒体、通知或系统级内容。
- 首期状态来源包括蓝牙连接/切换、自动化执行、自动亮度和主题切换。
- 多个事件更新同一灵动岛实例，不为每个事件另建窗口。
- 普通通知的服务、显示时长和布局不因灵动岛而改变。
- 不新增第三方依赖。

## 超级岛与默认通知的职责边界

- **超级岛用于展示状态，不以持续时长作为门槛**：短时间状态和长时间状态都进入超级岛。短时状态在显示一段时间后退场；长时状态在结束或取消后退场，期间可持续更新。状态更新应覆盖同一来源的旧状态，不保留过期状态。
- **默认通知用于常规通知**：一次性操作结果、提醒、错误或设置反馈，沿用现有通知队列、显示时长和布局；启用超级岛不应隐藏或改变默认通知。
- 状态表示 LumeKit 当前正在发生或刚发生的状态变化，短暂反馈（如设备已连接、亮度已调整）也属于状态，应进入超级岛；通知表示需要独立告知用户的信息（如提醒、错误说明或自动化消息），仍走默认通知。若状态变化本身伴随需要用户留意的说明，可同时更新超级岛并另发默认通知。
- 持续任务开始、进度变化、失败、完成等状态均可更新超级岛；只有确有额外告知价值时才发默认通知。高频状态刷新只更新超级岛，避免通知刷屏。
- 超级岛关闭或受场景抑制时，业务照常运行；需要告知用户的通知仍由默认通知送达。
- 首期只显示一个当前活动状态。多个来源同时活跃时，先确定替换行为并避免显示过期内容；是否排队、恢复被替换状态留待实际并发需求确认后再扩展。

### 现有通知候选盘点

依据当前通知调用点，以下判断是接入候选，不代表已经接入超级岛：

| 现有通知/来源 | 当前表现 | 建议归属 | 接入条件/说明 |
| --- | --- | --- | --- |
| 蓝牙输入/输出设备切换 | 成功后显示“音频已连接”，失败显示错误；切换本身有执行过程 | 成功连接/切换状态进入超级岛；失败说明仍可用默认通知 | 当前代码主要在完成后发通知。首期可将成功/切换结果映射为短时岛状态；若接入连接中等阶段，再扩展为连续状态更新。失败是否同时显示岛状态按状态视图设计确认，错误详情走默认通知 |
| 自动化流水线执行 | 执行结束后按设置通知成功、部分成功或失败 | 自动化执行状态适合超级岛；现有结束结果保留默认通知语义 | 当前执行器有整体执行过程和结束结果，但尚未发现通过岛呈现执行中的状态；接入时发送开始、关键进度、结束/失败状态，避免每个步骤造成频繁跳变 |
| 自动化动作“显示通知” | 动作触发时发一次短通知 | 默认通知 | 语义就是一次性消息，不应自动升级为持续岛状态 |
| 自动亮度 | 摄像头不可用时提示错误；亮度调整后提示结果；后台持续采样并调整 | 亮度调整结果属于短时状态，可显示在超级岛；自动亮度运行状态可作为长时状态候选；错误说明走默认通知 | 不要把每次采样/微调都显示成新状态；应在状态变化有用户感知价值时更新岛内容，并在停用/失败时结束或更新 |
| 自动深浅切换/计划任务 | 失败、未创建等提示 | 默认通知 | 均为一次性错误或操作结果；未来若增加明确的“正在等待日出/日落切换”可另评估是否值得常驻 |
| 快捷键提示/预览 | 按键触发或设置页预览时显示 | 默认通知 | 按键反馈和预览都是短暂提示，不属于持续状态 |
| 音频设备不可用、输入/输出切换失败 | 操作失败时显示错误 | 失败状态可进入超级岛；需要解释原因或提供额外信息时同时使用默认通知 | 区分“当前状态”与“错误说明”：状态由超级岛呈现，需用户留意的错误文案仍可作为常规通知 |

以上分类基于 `NotificationService` 的现有队列及调用位置。短时或长时的状态都属于超级岛展示范围；普通通知仍保留在现有默认通知路径。现有通知调用多以完成结果或错误提示的形式出现，接入时需区分其中的状态信息与通知说明，并从对应业务模块取得真实状态变化；采用两路展示时，状态更新岛内容，通知只负责额外告知，不重复刷屏。

## 主窗口状态与岛状态

| LumeKit 主窗口状态 | 灵动岛行为 |
| --- | --- |
| 正常显示 | 保持最小态，贴在屏幕顶部边缘，不遮挡主要窗口内容 |
| 最小化 | 进入常规态并展示当前状态摘要 |
| 最大化 | 默认保持最小态；用户指针在主窗口所在屏幕顶部中央触发区停留达到等待时间后，进入常规态 |
| 从最大化恢复或离开岛的交互区域 | 延迟收起，避免指针从触发区移向岛时提前隐藏 |
| 禁用灵动岛或应用退出 | 隐藏并释放定时器/事件订阅 |

顶部收起是视觉效果：窗口定位到显示器顶部边缘并与笔记本常见的黑色物理边框衔接，不依赖真实摄像头、屏幕挖孔或任何硬件遮挡。最大化悬停触发仅在主窗口最大化时生效，不因一般鼠标经过屏幕顶部而唤出。

## 交互规则

- 触发区为主窗口所在显示器顶部中央区域；由显示器工作区、DPI 和主窗口所在屏幕计算位置，不以摄像头或挖孔位置作为前提。
- 指针连续停留约 1 秒后呼出；等待时长应由设置控制，且设置范围需要在实现阶段确定合理上下限。
- 呼出后允许指针从触发区移动到岛本体。指针离开整个交互区域后等待短暂缓冲再收起。
- 点击收起态展开详情；再次点击或点击外部可收起。最小化状态下显示摘要，最大化悬停时允许查看详情。
- 不激活浮层窗口、不抢键盘焦点，不改变主窗口最大化状态或键盘输入目标。
- 主窗口恢复时优先收起灵动岛；如果当前动画或指针仍在岛区域，完成状态切换后最终仍应回到收起态。

## 视觉要求

- 超级岛是独立于常规通知的状态展示方式，不是用于弥补屏幕挖孔、摄像头区域或硬件遮挡的产物；没有挖孔的笔记本同样适用。
- 顶部出现的视觉依据是笔记本显示器常见的黑色物理边框。面板从显示器顶部向下展开：最靠近顶部的一端为黑色，向下逐步过渡到柔和的白色，表达从黑色边框进入屏幕内容区域的层次；渐变严格限制在灵动岛自身圆角面板内，避免形成刺眼的大块白色。
- 示意图定义三个固定层级：
  1. **最小态**：贴在屏幕顶部中央的最小黑色提示条，仅保留低调的存在感，不展示完整状态内容。
  2. **常规态**：由最小态向下展开为紧凑的状态摘要，展示图标、标题和必要的简短数值或结果；这是状态出现和自动收起前的默认可见形态。
  3. **详情态**：用户鼠标点击常规态后进一步向下展开，显示详情、进度或可用操作；再次点击或点击外部后收回常规态，再按既定延迟回到最小态。
- 文字和图标需在渐变两端均有足够对比度；详情态的内容区应以可读性优先，不因渐变降低文字辨识度。
- 动画以从上到下的短距离下滑和轻量展开为主，不要求液态变形或照搬手机动画。
- 支持系统深浅主题、DPI 缩放和多显示器；显示器选择以主窗口所在显示器为准。

## 架构建议

在 `BluetoothAudioReceiver/DeskBoxFloating` 内增加独立的 Island 状态模型、服务接口/实现和内容视图。状态协调器订阅主窗口状态及 LumeKit 内部状态源，决定更新、展开、收起或隐藏；`DeskBoxFloatingHost`/`DeskBoxFloatingWindow` 继续提供窗口承载能力。岛需有独立布局配置，避免修改普通通知配置或自动关闭路径。

建议状态至少表达：事件来源/类型、图标、标题、摘要、详情、开始/结束状态和可选进度。状态更新需可覆盖同一来源的旧状态；短事件完成后按策略清除，持续事件保留到完成/取消。多个来源同时活跃时使用明确优先级或队列策略，首期推荐优先显示最新的活跃状态，并在它结束后恢复仍有效的状态；若验证发现恢复规则复杂，则先做单一活动状态并记录被替换状态的行为。

## 设置

灵动岛设置放在现有悬浮通知设置附近：

- 总开关。
- 最大化时顶部悬停触发等待时间，默认约 1 秒。
- 展开后无交互的收起等待时间。
- 是否在游戏、全屏、视频、录屏/直播等现有通知抑制场景中隐藏。

设置持久化沿用现有 `IAppSettingsService`、`AppSettingsService` 和本地设置键模式。若现有抑制判断可安全复用则复用；不可直接将通知抑制与持续岛状态耦合时，应由 Island 协调器消费同一策略结果，而不是改变通知逻辑。

## 实施顺序

以下顺序用于控制实现风险，不缩减或改变上文已确认的最终需求。每阶段完成后先按对应验收点检查，再进入下一阶段；阶段拆分不代表后续能力可以忽略或默认不实现。

1. **基础状态与显示**：完成独立岛状态、单实例更新、总开关、最小化显示/恢复收起，以及蓝牙状态接入；验证普通通知不受影响。
2. **详情与状态扩展**：加入点击展开/收起、详情内容、展开后自动收起，并接入自动化、自动亮度和主题状态；验证状态生命周期及高频更新行为。
3. **最大化悬停交互**：加入顶部触发区、等待呼出、指针移入保持和离开延迟收起；验证不抢焦点且不误触。
4. **环境与场景适配**：完成多显示器、DPI、显示器布局变化、游戏/全屏等抑制设置，以及退出清理和持久化检查；进行 Debug 构建、自动化测试和人工窗口交互验收。

## 异常与边界

- 主窗口状态事件、鼠标轮询/事件和动画均需在 UI Dispatcher 上串行更新，避免并发改变窗口状态。
- 禁用、退出或窗口关闭时停止计时器并取消订阅，避免后台回调引用已关闭窗口。
- 主屏幕/显示器信息不可用时回退到主显示器顶部居中，并写入可诊断日志。
- 动画被新状态打断时，保证窗口最终位置与目标收起/展开状态一致。
- 游戏/全屏抑制和设置开关优先于活跃内容显示。

## 验收标准

1. 主窗口正常显示时灵动岛保持收起；最小化时显示摘要；恢复后收起。
2. 主窗口最大化时，指针在指定顶部区域停留达到设置时长才呼出；区域外移动不会误触。
3. 指针从触发区移动到岛本体时岛不提前收起；离开交互区后按延迟规则收起。
4. 灵动岛不抢焦点；主窗口最大化、键盘输入和普通通知行为不变。
5. 连续内部事件更新同一窗口；蓝牙、自动化、自动亮度、主题事件均可显示并按生命周期结束/恢复。
6. 收起态黑色胶囊、展开态上黑下白渐变在深浅主题和常见缩放比例下可读、无裁切。
7. 多显示器下灵动岛锚定主窗口所在显示器；显示器布局变化后不留在旧坐标。
8. 禁用开关、游戏/全屏等抑制规则有效；退出时无悬留窗口或计时器回调。
9. 自动化测试/单元测试覆盖状态协调、延迟触发、收起优先级和事件更新；最终执行项目 Debug 构建及人工窗口交互验收。
10. 蓝牙切换、自动化、自动亮度等现有通知按本需求的候选盘点分类：短时状态和长时状态都进入超级岛；普通通知及需要额外说明的信息仍走默认通知。
11. 超级岛关闭或场景抑制时不影响业务执行；应通知的关键结果不会因此丢失；高频状态更新不会造成默认通知刷屏。

## 风险与未决实现细节

- WinUI 主窗口最大化状态、非激活浮层和跨 DPI 指针触发区需要在当前 Windows App SDK/WinUIEx 版本上验证，不能仅凭编译视为视觉验收通过。
- Windows 工作区顶部通常不包含被任务栏占用区域；顶部边缘定位和中央触发区需通过实际显示器坐标验证，避免窗口被系统裁剪。
- 多个不同来源的持续事件可能需要优先级策略。先以可测试的单岛状态协调为边界，只有验收明确需要并发恢复时再扩展队列。
- 本需求不覆盖第三方应用集成、系统媒体控制、通知中心替代或独立第二窗口。
